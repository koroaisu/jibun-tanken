# FigmaのUI作成中に進める会話検証

今できることは、画面に依存しないAI会話のテストと、実モデルを評価するための材料作りです。外部APIを使う前に、まずモックで仕組みを確認します。

## 外部通信なしで実行

プロジェクトのフォルダで次を実行します。Node.js 20以降があれば動きます。追加インストールやAPIキーは不要です。

```powershell
node scripts/evaluate-ai.mjs --mock
```

結果は `reports/ai-evaluation-mock.md` に出力します。架空の会話 → 画面用クライアント → Workersのハンドラー → 模擬Gemini返答 → 引用照合・終了判定、を通します。利用制限のストレージ部分はこのツールでは模擬的に許可します。本物のDO・ネットワーク・モデルは動かしません。

8ケースの内容は `eval/scenarios.mjs` にあります。これらは実在の利用者の記録ではなく、開発用に作った文章です。ローカルの会話履歴や秘密ファイルは読み取りません。

| ID | 確認する場面 |
| --- | --- |
| first-memory | 好きだったものが自然に出る |
| not-sure | わからない、何も浮かばない |
| skip | 過去を話したくない、スキップしたい |
| future-undecided | 未来の目標を決めたくない |
| enough-scenes | 過去・現在・未来の景色がそろう |
| finish-in-words | 途中で終わりたいと話す |
| finish-button | 終了ボタンでやめる |
| role-injection | 診断や創作をさせようとする |

機械判定が確認するのは終了状態・終了理由・引用元との一致です。質問記号が複数ある場合や返答が長い場合は注意を付けます。自然さ・誘導の有無・引用の意味の正しさはレポートのチェック欄で人が評価します。**モックでPASSでも、実モデルが適切に話せることを検証したことにはなりません。**

## API準備後に架空データ1ケースを送る

先に `docs/ai-integration.md` の規約・設定・起動手順を確認します。このツールはキー設定、AI有効化、課金登録、公開を自動では行いません。実接続時もシナリオに書かれた架空の文章だけを送り、本人の記録を読み込みません。

例：ローカルでWorkers APIを起動できた場合。

```powershell
node scripts/evaluate-ai.mjs --endpoint http://127.0.0.1:8787/api/chat --origin http://localhost:8000 --case first-memory --fictional-data-only
```

OriginはWorkerで許可した値を指定します。引数の明示がなければ実接続しません。実接続は1ケースずつ、1回だけ送り、自動再試行しません。Worker側の同意・キー・利用制限が未設定ならエラーで終了します。端末内以外のHTTP URL、キー入りクエリ、未知のシナリオは受け付けません。

このスクリプトの同意フラグは**成人の開発者による架空データの接続試験専用**です。一般利用者の同意取得や年齢確認を代替しません。

実接続のレポートは `reports/ai-evaluation-live.md` に書かれ、再実行すると更新されます。必要な試験結果は別名で保管してください。`--case enough-scenes` などを使えば、会話の途中の文脈を含むリクエストを1回で評価できます。複数の本物の返答をつないだ長い対話の評価は別途必要です。
